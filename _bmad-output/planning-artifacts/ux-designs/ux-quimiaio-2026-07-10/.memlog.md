- (decision) Shifts (matutino/vespertino/nocturno) are display metadata only — shown as extra info on who registered and at what time; NOT a gate or control
- (decision) Corte de caja: user-initiated, typically done in the afternoon (before lunch break) — count what's in the cash drawer and leave change/fondo so the next day has sufficient change. UX needs a corte action available anytime, not tied to shift end
- (decision) Results capture clarified (business gap 2 resolved): interfaced studies receive values directly from analyzers into analyte fields, a quimico reviews then saves+validates; manual studies the quimico captures, saves, validates. Calculated analytes are NOT read-only — quimico can modify them. Quimico always analyzes results before printing, even in save+validate+print flow
- (decision) Save vs Validate semantics: Guardar = internal draft (not patient-visible). Validar = one button that validates all results; validated results become visible to the patient via QR token portal ONLY if paid — unpaid orders hide results from the patient portal even when validated
- (decision) Correction/change history on results is a system GOAL, not currently existing at the lab: no traceability today when someone captures wrong and corrects. Required for ISO 15189 accreditation (this lab is pursuing it); the quimico explicitly asked for this correction log. UX must surface result-change history (who, when, before/after)
- (decision) Validation granularity: PER STUDY — each study is a block with one Validar action that validates all its analytes at once. Portal visibility is incremental: each validated study becomes patient-visible immediately (paid gate always applies), and the patient is NOTIFIED per study as it becomes available (e.g. biometria today, urine test next day, culture in 3 days)
- (event) Image-analyte real workflow captured: used for equipment charts and PDF reports (antibiograms arrive as PDF). Current pain: screenshot the PDF, crop externally, upload, then trial-and-error pixel width/height until proportional. Purpose is reporting images/evidence; report is delivered as-is to avoid modification
- (event) Document-analyte real pain captured: current rich-text editor is rustic — cannot adjust it, report output does not match what was typed, quimico gets desperate and falls back to pasting an image instead. Intended use: observations/interpretations (e.g. written by the quimico)
- (decision) Image-analyte pattern decided: "captura = reporte" — in-app PDF/image crop (no external screenshot), auto-fit to report column width at 2-3 preset sizes (no manual pixel width/height), live report-accurate preview before validating
- (decision) Multi-page/multi-organism case resolved (quimico's own proposal, refined): image analyte holds a MULTI-EVIDENCE GALLERY, not a single image. Each "Agregar evidencia" adds one crop (from same or different source PDFs); each item gets an optional label (e.g. "Antibiograma — E. coli") rendered as a caption in the PDF; gallery items are drag-reorderable and print in that order. Handles cultures developing 1-3+ bacteria without re-upload/delete cycles
- (decision) Document-analyte pattern decided: constrained WYSIWYG editor limited to what the PDF template can actually render (bold, italic, lists, headings only — no option that can't survive export); editor uses the same font/width as the final PDF so what's typed is what prints; predefined snippets/phrases for common interpretations to reduce retyping
- (decision) Study-reordering-for-PDF pattern decided: drag-and-drop list of studies within the Captura screen — same interaction pattern as the image-analyte evidence gallery, kept consistent across the module
- (decision) Permission-matrix UI (Phase 2, FR-70) pattern decided: grouped by module — each module (Pacientes, Órdenes, Caja, etc.) is a header with its ~2-4 action toggles nested underneath, instead of a flat rol×permiso grid
- (decision) Branch/sucursal switcher (Phase 2, Red plan) pattern decided: topbar dropdown, e.g. "Viendo: Sucursal Polanco ▾" with a "Todas las sucursales" option for the consolidated multi-branch dashboard
- (decision) Accessibility floor set: WCAG 2.1 AA — minimum 4.5:1 contrast, full keyboard navigation, visible focus states. Applies across DESIGN.md tokens and EXPERIENCE.md Accessibility Floor section. Resolves the previously unspecified accessibility standard
